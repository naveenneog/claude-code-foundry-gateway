# claude-code-foundry-gateway — Coding-agent contract

> Generated by the `ironclad` skill. This file is **binding** for any agent working in this repo.
> The machine-checkable half lives in `.ironclad/charter.json` and is enforced by
> `node .ironclad/gate.mjs`.

## Read this first, every session

1. `docs/STATUS.md` — the ONE active packet and its acceptance criteria
2. `docs/ROADMAP.md` — what's planned, what's explicitly out of scope
3. `docs/UNKNOWNS.md` — what we know we don't know
4. `docs/CHARTER.md` — goals, non-goals, constraints, quality bar
5. `docs/adr/` — the latest decisions, and why

Then run `node .ironclad/gate.mjs --stage packet --no-run` to see where the repo actually stands
before touching anything.

## Contract precedence

When sources conflict, this is the order. **Never silently choose between conflicting sources** —
stop, and reconcile them in a new ADR.

1. Accepted ADRs in `docs/adr/`
2. `.ironclad/charter.json` (boundaries, budgets, commands)
3. `docs/CHARTER.md`
4. `docs/ROADMAP.md` acceptance criteria for the active packet
5. Existing implementation code

## Work selection

- Implement **only** the active packet named in `docs/STATUS.md`.
- Do not start a dependent packet early. Do not widen a packet with refactors, optional features or
  future abstractions — file them as new roadmap entries instead.
- "Later" items in the roadmap are **not** requirements.
- If the design is contradictory, stop and correct the design first, in writing.

## The loop (every packet)

```
PLAN → CONTRACT → RED → GREEN → REFACTOR → COUNCIL → GATE → LOG
```

- **RED first.** No production line before a test that fails *for the right reason*. Read the failure.
- **Never** skip, `.only`, delete or weaken a test, type, or constraint to get green.
- **Commit at every green.** Small, focused, conventional-commit subject, a body saying *why*.
- **Council:** Architect · Coder · QA · UX · Security — five explicit verdicts, recorded in
  `docs/STATUS.md`. Any BLOCK is fixed, and the fix gets a test.
- **Gate:** `node .ironclad/gate.mjs --stage packet` must exit 0. That is what "done" means.

## Non-negotiables

- Test-first; never fake green.
- Say what you don't know: log it in `docs/UNKNOWNS.md` **before** implementing, then research it
  (cite the source + date) or mark it an explicit assumption with a detector.
- Research rather than recall any version, limit, API shape, price or standard.
- No secrets in source, logs or error messages. `.env` is never committed.
- Validate every external input at the boundary; check authorisation per object, not just per user.
- Update the ledger in the same packet as the code: STATUS, CHANGELOG, README, ADR.
- Reuse what exists (modules, helpers, skills) before writing a parallel implementation.
- Never rewrite published git history.
- **Never disable the detector.** Loosening a budget, adding an allowlist entry or removing a check
  is itself a decision that needs an ADR and a stated reason.

## Commands

```
pwsh -NoProfile -File ./tests/Test-All.ps1                              # tests
node .ironclad/gate.mjs --stage pre-commit  # fast checks (also runs as the git hook)
node .ironclad/gate.mjs --stage packet      # definition of done
node .ironclad/gate.mjs --stage release     # + coverage floor, dependency audit, open unknowns
```

## Architecture boundaries

Declared in `.ironclad/charter.json` under `architecture.boundaries` and enforced on every commit.
An undeclared boundary is a preference, and preferences erode — if a rule matters, declare it there.
