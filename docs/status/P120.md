# P120 Chargeback membership from the projection sync job, 2026-10-21

### Why

`ClaudeCost()` attributes spend to today's business unit from a mapping that
`Publish-ClaudeQueries.ps1` bakes in from `bu-members` when an operator runs it.
On a projection gateway nothing writes `bu-members`, and a move between units
reached chargeback only after a manual republish.

### Acceptance criteria

1. After a successful full `--graph` run, the job prints membership lines
   (`"event":"projection-membership"`) with the run id, the run time, `part`,
   `parts` and `[oid, unit, parent]` rows, before the final summary line, which
   stays last.
2. Every membership line is at most 3,500 characters; parts are numbered
   1..`parts`; members without a unit are omitted; a run with no unit prints one
   line with no rows.
3. Snapshot, targeted, what-if and failed runs print no membership line.
4. `ClaudeCost()` uses the newest run, from jobs named `caj-renew-*` in the last
   three days, whose parts are all present; otherwise the published table.
   `membership_date` names the source.
5. The event name, the job-name prefix and the line bound agree across
   `sync/src`, `infra/projection-renewal.bicep` and `analytics/chargeback-cost.kql`.
