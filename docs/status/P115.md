# P115 Sync the live gateway into the onboarding record, 2026-10-14

### Why

`Update-ClaudeGateway.ps1` can recreate a missing decision record, but it also
plans gateway migrations. An administrator needs a narrower command that reads
the live deployment and writes only the local handover record.

### Acceptance criteria

1. `scripts/Sync-ClaudeGatewayRecord.ps1` reads one explicitly named APIM
   gateway, its API backend, non-secret named values and Claude deployments.
2. The command writes no Azure or Entra resource. Its only managed write is the
   selected local record path, using the repository's atomic JSON writer.
3. Live values replace stale record values for subscription, tenant, gateway
   URL, SKU, location, Foundry target, entitlement store, tier limits, request
   limit and model deployments.
4. Values Azure does not own use explicit precedence: command parameter,
   `entitlement-groups`, existing record. A missing standard group refuses
   before the record is changed; a new record defaults Desktop sign-in to the
   documented `helper-script` path.
5. Empty `models-standard` or `models-premium` means every live succeeded Claude
   deployment for that tier; an explicit list must resolve to live deployments.
6. An existing record is copied before replacement, unknown fields are
   preserved, and the resulting record has schema version 2 plus release and
   history evidence.

### Architecture

No component or network boundary changes. The script reuses the guided-flow
record writer and model-discovery helpers and produces the existing local
handover artifact.

### Unknown

U183 records which installer choices cannot be reconstructed from APIM and the
source precedence used instead.

### RED and GREEN

The first run of `tests/Test-GatewayRecordSync.ps1` failed because
`scripts/Sync-ClaudeGatewayRecord.ps1` did not exist. The first implementation
then exposed PowerShell 5.1 array, parser and test-stub scope differences, which
were corrected without weakening the assertions.

The final contract has 21 passing assertions under PowerShell 7 and Windows
PowerShell 5.1. It covers schema-v2 generation, live target and limit
discovery, custom gateway hosts, local-choice preservation, explicit and
allow-all tier models, failed-deployment exclusion, backup, release/history
evidence, missing-group refusal and new-record generation from
`entitlement-groups`.

Negative evidence includes:

- a simulated Azure write makes the read-only detector fail;
- a record for another gateway refuses before the first Azure read;
- a backend outside `<account>.services.ai.azure.com/anthropic` refuses;
- malformed `entitlement-groups` refuses instead of using stale local groups;
- Windows command metacharacters in Azure resource names refuse before `az`.

The two final negative cases were also run RED first. Before the production
guards, the foreign host advanced to an Azure account lookup and malformed
`entitlement-groups` replaced the record from local fallback values.

### Live dry run

`Sync-ClaudeGatewayRecord.ps1 -ResourceGroup rg-contosohub -ApimName
apim-claude-gw-fzgql9 -WhatIf` completed on 2026-10-14. It discovered Foundry
account `ai-contosohub530569751908` and succeeded Claude deployments
`claude-haiku-4-5`, `claude-opus-5`, `claude-opus-5-5` and
`claude-sonnet-5`. The SHA-256 of `onboarding/claude-gateway.json` was identical
before and after the command.

### Gate

The final packet gate ran at commit `93bc739f` on 2026-10-14 with an isolated
logged-out `AZURE_CONFIG_DIR`. Charter, ledger, architecture, security, Bicep
build and all static checks passed. The gate reported 20 passes, 3 warnings and
2 skipped checks, but `tests.run` failed because the repository command
`pwsh -NoProfile -File ./tests/Test-All.ps1` timed out after 3,600 seconds.

The P115 targeted contract, cross-PowerShell, documentation and live dry-run
checks passed before the gate. P115 is therefore implemented and committed but
is not marked fully gated; the repository-wide test timeout remains the blocker.
