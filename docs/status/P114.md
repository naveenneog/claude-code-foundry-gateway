# P114 Claude Office add-ins through the existing Foundry gateway, 2026-10-14

### Why

The Claude for Microsoft 365 add-in can route Azure AI Foundry requests through
an organization's gateway, but the browser task pane requires CORS. The live
gateway returned 404 for the preflight and no CORS headers on errors, so an
Office pilot could not start.

### Acceptance criteria

1. The API policy's first inbound child is a CORS policy allowing only
   `https://pivot.claude.ai`.
2. The policy permits the add-in's `GET` and `POST` methods and its required
   authentication and Anthropic protocol headers.
3. The policy exposes only documented gateway response headers needed by the
   add-in.
4. Negative tests reject a wildcard origin and missing required headers.
5. A live probe records preflight, unauthenticated error, and foreign-origin
   behavior without changing the tenant.
6. The existing Entra validation, entitlement, budget, content-safety and
   managed-identity path remains unchanged.

### Contract evidence

- Anthropic, [Use Claude for M365 with third-party platforms](https://claude.com/docs/office-agents/third-party-platforms), retrieved 2026-10-14.
- Microsoft Learn, [APIM cors policy](https://learn.microsoft.com/en-us/azure/api-management/cors-policy), retrieved 2026-10-14.
- ADR-0061 records the boundary and the no-second-gateway decision.

### Open unknown

U182 is closed only after the deployed policy proves whether APIM adds CORS
headers to policy-generated error responses.

### RED

Before the policy change, `tests/Test-OfficeGateway.ps1` failed because the
inbound policy had no CORS element. The disposable probe against the recorded
gateway on 2026-10-14 returned HTTP 404 for the preflight and HTTP 401 without
`Access-Control-Allow-Origin` for an unauthenticated POST. No Azure write was
performed by that probe.

### GREEN

The policy now places an explicit CORS block before `<base />`, allows only
`https://pivot.claude.ai`, and lists the required methods and headers. The
offline contract passes. `Test-SetGatewayPolicy.ps1`, the documentation
reference, documentation structure and Markdown suites pass. `az bicep build
--file infra/main.bicep --stdout` passes with the repository's existing
diagnostic-contract warning.

The request architecture source and generated request-path images were
regenerated successfully. The live probe remains intentionally failing until
the policy is deployed to an owner-approved or disposable gateway; that is the
remaining P114 live-evidence step.
