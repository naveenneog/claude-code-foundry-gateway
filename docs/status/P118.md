# P118 Installer model-family token quotas, 2026-10-19

### Why

The named-value installer asks for tier token limits and model allowlists, but
does not turn a monthly dollar allowance into separate Haiku, Sonnet, Opus,
Fable or Mythos counters. The reconciled USD control is delayed and can be
unavailable, while API Management can enforce a monthly token quota on Basic v2.

### Acceptance criteria

1. After model selection, an optional monthly USD allowance can be supplied for
   each tier. Zero leaves model-family quotas disabled.
2. The installer derives allowed families from selected deployments, divides
   the allowance equally across them and uses the most expensive selected
   deployment in each family at a stated output-share assumption.
3. The review names every allowed family, allocated dollars, blended list rate
   and suggested monthly token quota before any Azure write.
4. A selected family without a price refuses conversion and names the price-book
   remedy; missing price is never treated as free.
5. One non-secret `model-family-quotas` named value stores the canonical tier,
   family and token limits. A rerun without new dollar inputs preserves it.
6. APIM applies a monthly `llm-token-limit` keyed by user, tier and model family
   after model authorization. Empty configuration preserves current behavior.
7. Existing per-minute, daily, organization, business-unit and reconciled USD
   controls remain unchanged.
8. Tests cover calculation, deterministic serialization, unknown prices,
   installer/schema/Bicep wiring and the policy expression.
9. Guided-flow answer files and the browser installer expose the same optional
   tier allowances and output-share input, and preserve them through installer
   launch.

### Contract

[ADR-0064](../adr/0064-installer-model-family-token-quotas.md) records the
allocation and enforcement semantics. U196 records API Management behavior;
U197 records the equal-family allocation assumption.

Proposed and P117 live deployment remains paused.
