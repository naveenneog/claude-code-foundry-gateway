# P107 Administration scripts use the customer's own gateway, tier groups and budget choices, 2026-10-08

High priority at the owner's request (2026-10-08), ahead of P105 and P106. Branch `p107-customer-specific`.

### Why

A customer test on 2026-10-08 ran the business-unit menu and the sync from a fresh clone, on a machine without
the installer's onboarding record, against a gateway installed with the customer's own tier group names. Five
failures followed. In each, a script replaced a value it did not have with a built-in name, an empty string or an
implicit setting, instead of the customer's own value.

| # | Field symptom | Cause on `main` at `e9de3b4c` |
|---|---|---|
| B1 | `Sync-ClaudeAccess.ps1` and the menu's "Sync now" stop: "The standard tier group 'claude-code-standard' from the default name was not found in Microsoft Graph." | With no `-StandardGroup`, no `entitlement-groups` named value and no decision record for the gateway, the resolver falls back to the built-in names `claude-code-standard` and `claude-code-premium` (`scripts/ClaudeEntitlementGroups.ps1:70-81`) and stops on the missing standard group (`:99-101`). The decision record exists only on the machine that ran the installer (`scripts/Get-ClaudeGatewayTarget.ps1:35-46`). Gateways installed before P101 have no `entitlement-groups`, and a new projection gateway skips the sync that writes it (`scripts/ClaudeInstallProjection.ps1:274-275`). `scripts/Sync-ClaudeTurnstileGovernance.ps1:217-218` and the parameter defaults of eight projection and import scripts use the same built-in names. |
| B2 | `Manage-ClaudeBusinessUnits.ps1 -StandardGroup …` fails: "A parameter cannot be found that matches parameter name 'StandardGroup'." | The B1 refusal names `-StandardGroup` and `-PremiumGroup`; the menu has neither (`scripts/Manage-ClaudeBusinessUnits.ps1:29-34`), and its sync passes only the gateway (`:50`). |
| B3 | The menu header reads "Chargeback - <a group name> ()"; after a unit is written: "Cannot bind argument to parameter 'ResourceGroup' because it is an empty string." | The menu takes `-ResourceGroup` only from the decision record (`:30`) and accepts any text for the mandatory `-ApimName` (`:31`) without reading the gateway. `Set-ClaudeBusinessUnit.ps1` asks for an empty resource group itself (`:130-131`), but the menu's sync passes the empty value to `Sync-ClaudeAccess.ps1`, whose `-ResourceGroup` is mandatory. The unit is written and the sync then fails. |
| B4 | Every request from a new unit's developers returns 503 `usd_budget_state_stale`. | A unit's `-MonthlyBudgetUsd` also writes a dollar budget (`scripts/Set-ClaudeBusinessUnit.ps1:318-324,347`), a new unit is Strict (`:51`), and the menu passes no mode (`scripts/Manage-ClaudeBusinessUnits.ps1:141-146`). A Strict or Allowance scope with a dollar budget needs `usd-budget-state` reconciled within 15 minutes and matching five named values, or every request from it gets 503 (`infra/policy.xml:534-614`; [ADR-0026](../adr/0026-usd-budget-reconciliation.md): "An enabled dollar budget without a matching fresh state fails closed"). No reconciler runs unless one is deployed ([BUDGETS](../BUDGETS.md), steps 3 and 5), and a reconciliation with no dollar budget writes no state (`service/aum/aum_service/usd_reconcile.py:62-63`). |
| B5 | The unit writer warns that `quota-org` is below the units' total, and the menu continues. | The installer's organisation ceiling (`infra/main.bicep:104`, 100,000,000 tokens a month by default) stays in place when units are added; the writer prints an `az apim nv update` command (`scripts/Set-ClaudeBusinessUnit.ps1:371-390`) and the menu offers no change. |

The menu's unit prompt also pre-fills the group name `claude-bu-<id>` or `claude-team-<id>` and offers to create
it (`scripts/Manage-ClaudeBusinessUnits.ps1:120-136`).

The customer was unblocked on 2026-10-08 with explicit values: one sync with `-StandardGroup`, `-PremiumGroup`
and `-RecordGroups`, both gateway names on every menu run, and the dollar entries cleared (`Set-ClaudeUsdBudget
-Clear`) or the units set to `-Mode Notify`.

### Acceptance criteria

1. Given no `-StandardGroup` or `-PremiumGroup`, no `entitlement-groups` on the gateway and no decision record for
   it, `Sync-ClaudeAccess.ps1` looks up no built-in group name. In an interactive session it asks for the
   standard group and the premium group (display name or object id; premium may be `none`), shows each group's
   display name and object id from Microsoft Graph, and after confirmation syncs and records `entitlement-groups`;
   the next run asks nothing. Without a console it stops before any write with the full command for this
   gateway, including its `-ResourceGroup` and `-ApimName`.
2. A new gateway records `entitlement-groups` with the object ids of the groups it was installed with, for both
   stores, including a new projection gateway.
3. Called without group parameters, `Sync-ClaudeTurnstileGovernance.ps1`, `Deploy-ClaudeProjection.ps1`,
   `Deploy-ClaudeProjectionRenewal.ps1`, `Sync-ClaudeProjection.ps1`, `Import-ClaudeEntitlement.ps1` and the
   projection switch and preflight use the gateway's `entitlement-groups`, else this gateway's decision record,
   else stop before any write naming `-StandardGroup` and `-PremiumGroup`. No script falls back to
   `claude-code-standard` or `claude-code-premium`. The installer keeps its named defaults: they are shown in its
   review before any write and recorded (criterion 2).
4. `Manage-ClaudeBusinessUnits.ps1` takes `-StandardGroup` and `-PremiumGroup` and passes them to every sync it
   runs.
5. `Manage-ClaudeBusinessUnits.ps1` resolves the gateway before showing the menu: its parameters, else
   `CLAUDE_RG`/`CLAUDE_APIM` or the decision record, else the shared chooser in an interactive session, else it
   stops naming the parameters. It reads the gateway and stops, naming the values it tried, when the gateway
   does not exist. The header and every script the menu starts get the same two values.
6. A dollar budget is not enforced as a side effect. `Set-ClaudeBusinessUnit.ps1 -MonthlyBudgetUsd` on a Strict
   or Allowance unit writes the dollar budget only when the gateway's `usd-budget-state` is valid now, or with a
   new explicit switch `-EnforceUsd`; otherwise it writes the token budget and states that the dollar budget is
   not enforced until a reconciler runs, with the commands. A Notify unit's dollar budget, which only reports
   usage, is written as today.
7. When the gateway holds a dollar budget for a Strict or Allowance scope and its `usd-budget-state` is not
   valid, `Set-ClaudeBusinessUnit.ps1`, `Sync-ClaudeAccess.ps1` and the menu name the scopes whose requests return
   503 `usd_budget_state_stale` and give both remedies: deploy the reconciler, or clear the dollar budgets.
8. When the units' monthly total exceeds `quota-org`, the menu asks whether to raise `quota-org` to that total
   (default no) and writes it through the shared named-value writer on yes; the script path keeps its warning and
   command.
9. The menu's unit prompt pre-fills no group name: the operator names the customer's group, and creation is
   offered for that name only.
10. BUSINESS-UNITS, BUDGETS, TROUBLESHOOTING and the CHANGELOG describe the behaviour, with a troubleshooting row
    for each field symptom.
