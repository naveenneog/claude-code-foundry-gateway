# P108 Dollar budgets are enforced correctly once a reconciler runs, 2026-10-08

High priority at the owner's request (2026-10-08: "identify why the USD reconciler is a problem, test thoroughly
and make sure every functionality of it is working properly"). Branch `p108-usd-reconciler`, from `main` at
`489082b1`. P107, on branch `p107-customer-specific`, records the reconciler's operational dependencies; this packet
fixes how it prices and attributes usage.

### Why

On 2026-10-08 a live test ran against a gateway installed from `main`. It used the projection store and tier
groups named the way the customer names them. One unit had a $50 monthly budget in Strict mode. The reconciler
was deployed with `scripts/Register-ClaudeUsdReconciler.ps1 -RunNow`.

| # | Observed | Cause |
|---|---|---|
| R1 | After the first reconciliation the unit was served. After a few more requests every member of the unit got 403 `usd_budget_unpriced` ("Usage cannot be completely priced for this scope. Ask the gateway owner to correct the dated price book."), with `unpriced_models: ["unattributed-usage"]`. | The ledger query groups usage by day, user and deployment, and keeps a unit only when the day has one (`service/aum/aum_service/usd_reconcile.py:31-43`: `by day, user_id, deployment`, `units=make_set(business_unit, 2)`, `business_unit=iff(array_length(units) == 1, …)`). The developer had been unassigned in the morning and in the unit in the afternoon, so the day's row had units `["unassigned","finance"]` and no unit. A row without a unit adds `unattributed-usage` to every dollar-budget scope on the gateway (`usd_budgets.py:231-241`). The row stays in the month, so every Strict or Allowance unit with a dollar budget is refused until the month ends. |
| R2 | The developer's requests used the deployment `claude-haiku-4-5` (model `claude-haiku-4-5-20251001`). | The reconciler looks up the deployment name exactly (`usd_budgets.py:166-172`, `price_row`: `book.get("models", {}).get(deployment)`). The shipped price book (`config/price-book.example.json`, dated 2026-09-16) has `claude-haiku-4.5` and no `claude-opus-5-5`, while the Foundry deployments are `claude-haiku-4-5` and `claude-opus-5-5`. The chargeback query matches names after normalising them (`analytics/chargeback-cost.kql:56-63`), so the workbook prices usage that the reconciler refuses. |
| R3 | — | A ledger row without a user adds `unattributed-usage` to every scope (`usd_budgets.py:231-241`). A row without a user cannot be the spend of any member or person scope. |

### Acceptance criteria

1. The ledger query groups by day, user, deployment and the unit stamped on the request. Each row is attributed:
   - on a projection gateway, to its stamped unit;
   - on a named-value gateway, as today: the current membership, else the stamp.

   A developer who changes unit within a day is charged to each unit for that unit's own requests, and no
   ambiguous row is produced.
2. A ledger row without a user counts towards no unit or person scope. The reconciler reports such rows (count
   and tokens) in its output. ADR-0060 records why: such a row cannot be a member's spend.
3. A deployment or model matches a price-book entry when the two names are equal after normalisation: lowercase
   letters and digits, as in `analytics/chargeback-cost.kql`. A trailing eight-digit date version also matches
   (`claude-haiku-4-5-20251001` matches `claude-haiku-4.5`). A shorter family never matches: `claude-opus-5-5`
   does not match `claude-opus-5`. One shared rule serves the reconciler and the PowerShell price readers, and a
   test proves that the reconciler, `scripts/ClaudeBusinessUnit.ps1` and the KQL agree on the same names.
4. The shipped price book has an entry for every Claude model the installer can offer, including
   `claude-opus-5-5`. Each entry carries list prices cited from the published Claude pricing page, with its
   date.
5. A scope is `unpriced` only for its own rows whose model has no entry. The 403 message names the model and the
   price book; ADR-0026's rule that an unpriced row is never $0 stays.
6. No regression:
   - `tests/Test-AumService.ps1` (pytest), `tests/Test-UsdBudgets.ps1`, `tests/Test-UsdPolicy.ps1`,
     `tests/Test-UsdReconcilerSchedule.ps1`, the chargeback suites and the AUM CLI USD tests
     (`cli/finops/tests/test_usd_budgets.py`) pass with an equal or higher count;
   - the state format the policy reads (`compact-v1`, `policy_revision`) is unchanged.
7. Live, on the P107 test gateway whose unit R1 blocks: the reconciler deployed from the P108 commit serves that
   unit again. A unit with a small budget reaches 403 `usd_budget_exceeded` after spend, and raising the budget
   serves it again; each step is timed.
