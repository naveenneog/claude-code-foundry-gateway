# P96 status

## P96 Fixes from a live deployment, 2026-10-05

**Stage:** COUNCIL. P96 is on `p96-field-fixes`, based on `main` `ee7b486`. The owner approved its
scope and its merge on 2026-10-05, as fixes the size of decision 14 (a case-sensitive business unit
identifier check), after its council and packet gate. No live Azure or Entra call is part of this
packet. Every `az` call in tests and gates uses an isolated, logged-out Azure CLI configuration
directory (`AZURE_CONFIG_DIR`).

### Why

- During a live deployment on 2026-10-05, `scripts/Set-ClaudeBusinessUnit.ps1` given a new
  identifier with a capital stopped with "Invalid USD scope identifier.", which does not state the
  rule. `Test-ClaudeBuId` (`scripts/ClaudeBusinessUnit.ps1`) matched its pattern without regard to
  case; the dollar budget accepts only lower-case scope identifiers
  (`scripts/ClaudeUsdBudgets.ps1:42`). Read on `ee7b486`, the same check let the AUM catalog action
  (`scripts/Invoke-ClaudeFinOps.ps1`) write such an identifier to `bu-registry`, and a capitalised
  spelling of a stored unit, such as `Sales` for `sales`, matched that unit because PowerShell's
  `-eq` ignores case. The interactive manager (`scripts/Manage-ClaudeBusinessUnits.ps1`) accepted
  the identifier at its prompt and offered to create the Entra group before the writer refused it.
- The P95 council recorded that `Start-ClaudeGateway.ps1 -Action Change` gives the Tier and Desktop
  sign-in plans no snapshot path ([ROADMAP](../ROADMAP.md), P95 follow-ups). `-Change sku` and
  `-Change desktopSignIn` therefore stop at their write gate with "A named-value snapshot path is
  required before applying this lifecycle change." Start keeps a step's `Initialize-ClaudeFlowStep`
  as its preparation (`Start-ClaudeGateway.ps1:154-176`), and only the Entitlement step defined one.

### Decisions

1. A new identifier is checked with case. An identifier that the registry holds with the same
   spelling keeps only the map rule (no space, comma, equals or colon): before P96 the check ignored
   case, so a registry can hold capitals, and refusing them would block changes to an existing unit.
   `Set-ClaudeBusinessUnit.ps1` (unit and parent) and the AUM bridge's budget and catalog actions pass
   the registry's identifiers to `Test-ClaudeBuId -Registry`. `ConvertTo-ClaudeBuRegistry` passes
   `-Stored`, because a serializer's rule is map safety and its callers check new identifiers first.
   Added in council round 1: an identifier that matches a registry entry only when case is ignored is
   refused with the stored spelling, and the writers compare identifiers by exact spelling (`-ceq`,
   `-cne`, `-cnotin`; the AUM catalog keeps its seen set and parent map by exact spelling), so a
   registry that holds two spellings of one identifier keeps them as two units. Added in council
   round 2: "known" means the same characters (ordinal), because `-ccontains` compares by culture and
   takes U+212A KELVIN SIGN for `K`; the AUM catalog checks each `parent_id` with `Test-ClaudeBuId`,
   because `-cnotin` ignores U+00AD; `ConvertFrom-ClaudeBuModes` keys by exact spelling, and a budget
   mode, Strict included, is refused for an identifier with capitals, which `bu-modes` cannot hold;
   and the writers (`Set-ClaudeBusinessUnit.ps1`, the AUM bridge) read `bu-parents` with
   `ConvertFrom-ClaudeBuParents -ExactKeys`. Without the switch the parser still reads `bu-parents`
   without case: the renewal job mirrors it on purpose (`sync/src/business-units.mjs`, P94), and
   `tests/Test-ProjectionRenewalRuns.ps1` checks that the two agree, so changing the readers is a
   decision about the job as well ([ROADMAP](../ROADMAP.md) follow-up). The Turnstile budget pull
   (`Compare-ClaudeTurnstileBudgets`, `scripts/Sync-ClaudeTurnstileGovernance.ps1`) matches units by
   exact spelling too.
2. `Confirm-Identifier` in `scripts/Manage-ClaudeBusinessUnits.ps1` runs the writer's `Test-ClaudeBuId`
   (council round 1; first a copy of its rule), so the prompt refuses a new identifier with the writer's
   message before the Entra group is offered. Since council round 2, `Add-Unit` reads `bu-registry`
   first and passes it to the check; a failed read stops it before any group is looked up or created.
3. One helper, `Initialize-ClaudeFlowLifecycleSnapshotPath` in `scripts/flow/lib/LifecycleCommon.ps1`,
   names the snapshot for the Entitlement, Tier and Desktop sign-in steps:
   `backups/before-<step>-<gateway>-<UTC time>.json`. The Entitlement name is unchanged. The snapshot
   is taken at the step's write gate. A Tier choice that needs a new instance passes the gate and then
   stops before any Azure write, so its snapshot is the backup that the move restores
   (`scripts/flow/Tier.ps1`, Invoke-ClaudeFlowStep).
4. Not in P96, recorded in [ROADMAP](../ROADMAP.md): Turnstile apply's identifier check
   (`scripts/ClaudeTurnstileApply.ps1:86,99`); what a unit stored with capitals cannot do (a dollar
   budget, a budget mode, the chargeback report); and the exact-name group lookup (decision 10, in
   the security packet).
5. No ADR. The rule is the documented contract ([BUSINESS-UNITS](../BUSINESS-UNITS.md#adding-a-business-unit),
   the `-Id` help in `scripts/Set-ClaudeBusinessUnit.ps1`); no structure, boundary, storage or
   dependency changes. No architecture change: no component, data flow, identity, schedule or network
   path changes. The architecture manifest's source hashes follow the changed scripts; the 19 images
   are unchanged.

### Acceptance criteria

1. Given a registry that does not hold it, an identifier with a capital is refused with the lower-case
   rule before any write by `Set-ClaudeBusinessUnit.ps1` (`-Id` and `-Parent`), the AUM bridge's
   budget and catalog actions and the manager's prompt.
2. Given a registry that holds `sales`, `Sales` is refused, not taken as that unit, by
   `Test-ClaudeBuId`, `Set-ClaudeBusinessUnit.ps1` and the AUM budget action.
3. Given a registry that holds `Legacy-Unit`, its group, parent and token budget can be changed, it
   can be a parent, the AUM catalog keeps it, and the registry with it is written; an identifier that
   could break the map is refused even when the registry holds it.
4. Prepared as Start prepares them, the Tier and Desktop sign-in steps name their snapshot under
   `backups/` as `before-tier-<gateway>-` and `before-desktop-sign-in-<gateway>-`, and the write gate
   takes it.
5. The Entitlement step keeps `before-entitlement-<gateway>-<time>.json`; a plan with no actions gets
   no snapshot path; a plan that names its path keeps it.
6. Added in council round 1. Given a registry that holds `Legacy-Unit`, the spelling `legacy-unit` is
   refused with the stored spelling, before any write, for a change of group, a removal, a parent, the
   AUM budget action and the AUM catalog. Given a registry that holds both `sales` and `Sales`, a
   change of group and a removal through `Set-ClaudeBusinessUnit.ps1`, the AUM budget and mode actions
   and the AUM catalog act on the exact spelling and keep the other unit, its budget and its team; the
   catalog writes a team for each spelling it is given, removes the mode of the spelling it removes,
   and refuses a team whose parent is another spelling of a unit. The manager's prompt shows the
   writer's message.
7. Added in council round 2. With `sales` and `Sales` stored, removing `Sales` keeps the mode of
   `sales`; removing `Sales`, clearing its parent or giving it a parent keeps the parent entry of
   `sales`; moving a team from `Sales` to `sales` writes the new parent; the AUM budget action takes
   `Sales` as a unit when `sales` is a team; and a Turnstile budget for one spelling is compared with,
   and written to, that unit only. A budget mode, Strict included, is refused for an identifier with
   capitals, before any write, in the script and the AUM bridge. A look-alike of a stored identifier
   (U+212A for `K`) is not known and is refused, in `Test-ClaudeBuId` and the AUM catalog, and so is a
   catalog `parent_id` with U+00AD. The manager reads `bu-registry` before the Entra group step,
   refuses `legacy-unit` with `Legacy-Unit` stored there, stops there when the read fails, and reaches
   the group step for a new lower-case identifier.
