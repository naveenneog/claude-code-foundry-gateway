### Decisions

The owner was not available on 2026-10-04 when these were asked. The recommended options are
recorded here and remain open to the owner's review:

1. Two packets: P94, then P95 (the switch-over) after this packet's gate.
2. The job reads `bu-registry` and `bu-parents` through ARM on every run, with a read-only role,
   and orders units as `Sort-ClaudeBuByDepth` does.
3. Offline proof only. The live steps are a runbook for the owner.
4. `sync/package-lock.json` is committed and the image installs with `npm ci`.
5. A Linux CI job builds the image and runs its entry point.

[ADR-0049](../adr/0049-projection-renewal-deployment.md) records the design and the options.

### Acceptance criteria

1. Given the package written by the staging function, every relative import of every module in it
   resolves inside the package, and every bare import is a `node:` built-in or a dependency in
   `sync/package.json`. `apply-projection.mjs` and `check-admission.mjs` start from a copy outside
   the repository, with stand-in Azure SDK modules, and print their own argument errors. The runner
   archive, the Dockerfile and the guide's runner commands use the package layout.
2. Given no VNet input, `infra/projection-network.bicep` creates a `/27` subnet delegated to
   `Microsoft.App/environments` that overlaps no other subnet in the default plan, and outputs it as
   `renewalSubnetId`. Given an existing VNet, the supplied `renewalSubnetId` passes through.
3. `infra/projection-registry.bicep` creates the registry, the job identity and its AcrPull role.
   `infra/projection-renewal.bicep` uses them as existing resources and creates no registry.
4. The job sets `AZURE_CLIENT_ID`, the tier group object ids and the gateway resource id, with no
   command or args override; the image command is `--graph`. Each run reads `bu-registry` and
   `bu-parents` and orders units as `Sort-ClaudeBuByDepth` does; a failed read writes nothing.
   Admission refuses a job definition without these settings.
5. The environment sends console logs to the gateway's Log Analytics workspace through a diagnostic
   setting. Each alert filters on the job name, returns rows only when unhealthy and matches an
   event the job prints; a test binds the alert text to the job's events.
6. Given a stubbed `az`, `scripts/Deploy-ClaudeProjectionRenewal.ps1` deploys the registry, builds
   the image from the package, reads back a `sha256:` digest, deploys the job with it, prints the
   tenant-admin grant command and the receiver confirmation step, and writes a receipt, in that
   order. An invalid email, group id or digest, a missing renewal subnet, or a refused build stops
   it before its next write.
7. Given stand-in Graph, Cosmos and ARM responses and a controlled clock, a snapshot population
   followed by three job runs 30 minutes apart passes the admission checker. A Graph refusal writes
   no record and no status. A changed `bu-registry` reaches the records on the next run.
8. `docs/SECURE-PROJECTION.md` and `docs/AZ-COMMANDS.md` give the deployment order, with
   citations. The guide guard checks the parameters of every template the guide deploys.
