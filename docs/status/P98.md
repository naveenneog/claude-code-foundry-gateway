# P98 The installer deploys the Cosmos projection by default, 2026-10-06

[ADR-0052](../adr/0052-cosmos-default-installer.md) records the decision. This file records the evidence.

### Why

Before P98 the installer's projection choice changed only the recorded store. The deployment ran only
with `-DeployProjection`, which no prompt set, and the switch needed a renewal receipt that the installer
never produced. A customer who chose the projection got a gateway still serving named values. The owner
asked on 2026-10-05 for the Cosmos-based installer to be the recommended and default path, with named
values for small organisations only, and for choosing Cosmos to deploy it. They also asked for SKU
guidance at scale and for documentation that opens with the first command.

### Decisions

ADR-0052, from the P98 contract (E1 to E9):

- the projection is the default and recommended store for every size; named values above their
  capacity are refused;
- choosing the projection deploys it, then switches the gateway through P97's switch;
- the resolver is public by default on every tier; private needs outbound virtual network integration;
- `-DeploySyncJob` deploys the optional sync job;
- the SKU guidance cites cache, units, network and zone facts;
- the next steps name the targeted sync and the developer setup;
- README, Setup and the projection guide open with a quickstart;
- `scripts/Test-ClaudeLiveProjection.ps1` proves the path on a disposable gateway.

Amended in council round 1 (ADR-0052): a re-run on an existing named-value gateway without
`-EntitlementStore` migrates it to the projection, and the approval summary says so; a gateway already on
the projection keeps it and its resolver access; above named-value capacity the comparison baseline is a
fresh Entra snapshot; zone redundancy and Premium v2 virtual network injection are creation-time choices
that the installer does not provision.

### Acceptance criteria

1. `-Yes` without `-EntitlementStore` chooses the projection; the choice lists it first as recommended;
   named values for more developers than they hold are refused, before anything is created, with the
   capacity reason.
2. Choosing the projection runs `Deploy-ClaudeProjection.ps1` to deploy, populate and compare, then
   again with `-FlipAfterCleanCompare`. A failed deployment runs no switch and names the deployment
   rerun; a refused switch names the switch rerun; both leave named values serving. A new gateway gets no
   named-value lists, and the deployer's compare and the switch compare it with a fresh snapshot.
3. `-WhatIf` lists the projection steps in the approval summary and changes nothing.
4. The resolver defaults to public on Basic v2, Standard v2 and Premium v2; a private resolver on Basic v2
   is refused; on Standard v2 or Premium v2 the installer states the outbound integration prerequisite.
5. `-DeploySyncJob` passes the tier groups and an alert address to the job's deployment; a failure there
   warns with the rerun command and does not end the installation.
6. The live verifier refuses unsafe inputs and the default Azure CLI profile before any Azure call,
   prepares the groups before the installer, checks the switch, and proves 200, 403 after a removal and
   targeted sync, then 200 after re-adding; `-Teardown` deletes what the run created, even after a
   failure, and never a resource group that existed before.

Added in council round 1:

7. A re-run without `-EntitlementStore` on an existing named-value gateway shows "projection (migrating
   from named values: deploy, compare, switch)" in the approval summary and migrates it; a gateway already
   on the projection stays there and keeps its resolver access; `-EntitlementStore named-value` keeps
   named values.
8. Above named-value capacity, `-CompareBaseline Snapshot` makes the deployer and the switch compare the
   projection with a fresh Entra snapshot, with no named-value refresh. The named-value refusal checks
   `-DeveloperCount`, or the tier groups' distinct members, also under `-Yes` and `-Sku`.
9. Every argument the installer passes to a deployer is a parameter of the real script, with a value
   that the parameter's fixed set allows.

### Live verification

Two runs of `scripts/Test-ClaudeLiveProjection.ps1` on 2026-10-06, in the owner's test subscription and
tenant, on a disposable Basic v2 gateway in East US 2 calling the standard tier's `claude-haiku-4-5`
deployment. The verifier set `entitlement-cache-seconds` to 60 on the disposable gateway and polls each
expected status (`scripts/Test-ClaudeLiveProjection.ps1:84-91`).

1. **Run 1, at `332146f`, stopped at the projection deployment.** The installer deployed the gateway
   and skipped named-value lists for the new gateway. `Invoke-ClaudeInstallerScript` then splatted the
   deployer's arguments as a string array, which PowerShell binds by position: "Cannot validate argument
   on parameter 'Sku'. The argument "clive29ce086d87" does not belong to the set
   "BasicV2,StandardV2,PremiumV2"". The installer reported "Projection deployment failed; named values
   keep serving and nothing was switched" with the deployment rerun command (acceptance criterion 2).
   The teardown deleted the resource group, both groups and the resolver app, and the soft-deleted gateway
   was purged. `5c57f8c` passes the arguments by name and checks the binding against a probe script that
   copies the deployer's parameter types; `7abfedf` checks every argument against the real deployers'
   parameter blocks (criterion 9).
2. **Run 2, at `5c57f8c`, passed: 04:59 to 05:48 IST, 48 minutes.**

| Step | Result |
|---|---|
| Groups created before the installer, with the signed-in operator in the standard group | 2 created |
| Installer with `-EntitlementStore projection` | Gateway deployed; projection deployed, populated, compared and switched |
| Switch | `entitlement-source` is `projection`; `entitlement-projection-prefix` names the deployment |
| Entitled request through the gateway | HTTP 200 on the first request |
| Removed from the group, then `Sync-ClaudeAccess.ps1 -User` | `written=0 deleted=1`; HTTP 403 on the first request after the sync |
| Re-added to the group, then `Sync-ClaudeAccess.ps1 -User` | `written=1 deleted=0`; HTTP 200 on the first request after the sync |
| Teardown | Role assignments on the Foundry account, the resolver app, the resource group and both groups |

After run 2, `az group show` reported the resource group as Deleting, neither group nor the resolver app
existed, and the soft-deleted gateway was purged with `az apim deletedservice purge`.

Run 2 did not exercise the default store: the verifier at `5c57f8c` passed `-EntitlementStore projection`,
and at that commit the installer without `-EntitlementStore` stopped at its first prompt (council round 1,
Coder; fixed in `efad6ae`). The verifier now runs the installer without the parameter.
