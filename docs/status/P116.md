# P116 Configurable Cosmos access profiles, 2026-10-14

### Why

Customers require configurable access tiers and group mappings. The supplied configuration has nine commercial plans and 47 Entra-backed access profiles combining Code, Cowork, Chat, Design, Haiku, Sonnet, Opus, Fable, Mythos and optional M365. The current projection accepts only `standard` and `premium`.

### Scope

P116 builds the Cosmos access-catalog foundation, profile group reconciliation, one-point-read resolver shape, model-family enforcement, script-based configuration and scheduled automatic publication. Business units stay independent. AUM and Turnstile changes are excluded. Existing explicit P108 dollar budgets and their cached reconciled decisions must continue to work; automatic plan-derived dollar defaults are a later packet.

### Acceptance criteria

1. A versioned JSON catalog supports 1-16 plans and 1-64 enabled profiles, canonical capabilities, Haiku/Sonnet/Opus/Fable/Mythos model families, optional M365, unique profile priorities and Entra group object IDs.
2. A tested administrator command validates, previews, backs up and publishes the catalog as one tenant-bound Cosmos control document without changing Entra membership.
3. Full and scheduled projection syncs resolve catalog profile groups, choose one whole highest-priority profile, keep BU assignment independent, and stop before writes on an absent access group, ambiguous top priority or malformed catalog.
4. User records contain plan, profile, capability, model-family, connector, catalog-version and profile-hash fields while retaining the compatibility `tier`, tenant, BU and reconciliation evidence.
5. The resolver still performs one Cosmos point read, accepts legacy records during migration, rejects malformed expanded records and returns the new fields under a versioned APIM cache key.
6. Projection-backed requests enforce the resolved model families before Foundry. Named-value Standard/Premium behavior and rollback remain unchanged. Client capability and M365 configuration is generated for MDM and is not described as a security boundary.
7. Group membership changes write only changed users. The current apply lock, removal ceiling, full-sync status evidence, alerts and schedule behavior remain.
8. Existing explicit organization, BU and user dollar budgets retain P108 pricing, freshness, caching and refusal behavior for profile-backed requests. No automatic plan-dollar enforcement is claimed without reconciler changes.
9. A live disposable Azure run publishes a catalog, moves a test identity between profiles, proves model allow/refusal and resolver caching, verifies the existing dollar refusal path, and either proves scheduled automatic publication with `GroupMember.Read.All` or records the existing U17 tenant-admin block without weakening it.
10. For Standard v2 or Premium v2 with a private resolver, setup selects either a managed projection VNet or explicit customer VNet and dedicated subnet IDs before Azure writes. Preflight checks region, subscription, subnet delegation and private DNS prerequisites; the selected network is used for APIM outbound integration, Cosmos and resolver private endpoints, the in-network runner and the renewal job.
11. Architecture sources, administrator documentation, migration/rollback steps, council verdicts and packet-gate evidence are recorded on branch `PRODUCTION`.
