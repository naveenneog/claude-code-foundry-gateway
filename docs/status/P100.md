# P100 The update flow moves a named-value gateway to the Cosmos projection, 2026-10-06

[ADR-0054](../adr/0054-update-flow-entitlement-migration.md) records the decision. This file records the evidence.

### Why

On 2026-10-06 the owner asked for a path that moves an existing gateway from named values to the Cosmos
projection with few commands, inside the update flow. It reuses the gateway's previous tier groups, business
units and entitlement, checks quotas and prerequisites, and shows the resources, networking and cost before
anything is written. The owner placed this ahead of the P99 merge. Before P100:

- the installer's re-run migrated a gateway, but asked again for the tier groups and checked no quota, region or
  effective role-assignment right;
- the update flow (`scripts/Update-ClaudeGateway.ps1`) had no migration for the entitlement store and stopped
  without a local decision record;
- the plan for a migration showed the steps and a modelled cost, but not the resources, the network or the
  readiness of the subscription.

### Decisions

ADR-0054: migration `0004-entitlement-projection` in the update flow; previous values from parameters, the
gateway, the decision record or the default names, each verified in Entra; readiness checks in the plan, where a
FAIL blocks the apply; the installer's functions do the named-value refresh, the deployment, the population, the
comparison and the switch; the tier groups are recorded on the gateway in `entitlement-groups`.

### Acceptance criteria

1. Given a named-value gateway and its decision record, `Update-ClaudeGateway.ps1 -ResourceGroup <rg> -ApimName
   <apim>` plans the migration with no other parameter. The plan names the tier groups and where they came from,
   with their Entra member counts against `allow-standard` and `allow-premium`, and the business units,
   developers, name prefix, region, SKU and resolver access.
2. Without a decision record, the same command plans from the live gateway. The default-named groups are used
   when Graph finds them. Otherwise the plan is blocked and names `-StandardGroup` and `-PremiumGroup`.
3. The plan lists readiness checks as PASS, WARN, FAIL or NOTE, each with a remedy:
   - PowerShell 7;
   - the projection preflight;
   - region availability for Cosmos DB, container groups, private endpoints and Flex Consumption;
   - usage against limits: container groups and cores, storage accounts and virtual networks in the region;
     Cosmos DB accounts and private DNS zones in the subscription;
   - the right to create role assignments;
   - template validation, where a policy denial is a FAIL.

   A FAIL blocks `-Apply` with its remedy, and nothing is written.
4. The plan lists each resource to be created (name, type, SKU, region), the network (address space,
   subnets, private endpoint, DNS zones, resolver access, runner), the identities and role assignments, the
   monthly cost and a time estimate. A test compiles the templates and fails when a resource type in them is
   not in the inventory, or the inventory names a type they do not create.
5. Drift between named values and Entra shows in the plan as counts of developers who would gain or lose
   access. The apply refreshes the named values first, as the installer does.
6. `-Apply -ApprovedPlanFingerprint <fingerprint>` takes the backup, refreshes the named values, deploys,
   populates, compares and switches, records `entitlement-groups`, and verifies that `entitlement-source` is
   `projection`. A failed step leaves named values serving, and the error names the update command that resumes.
7. A gateway already on the projection plans no migration.
8. `-KeepNamedValues` plans no migration and says that the gateway keeps named values.
9. Live: a disposable named-value gateway moves to the projection with the plan and the apply alone. A
   developer's request returns 200 before and after the move, and the resources are deleted.

Found while wiring the updater, each with a test that failed first:

- Before `b4f3c795` the updater called each migration's Test without its plan. On a gateway that stays on named
  values (a discovery without migration facts, or `-KeepNamedValues`), 0004's Test read
  `entitlement-source=named-value`, so the whole update failed with "Migration '0004-entitlement-projection' did
  not verify". `b7dc7ad5` runs that apply offline; on the earlier updater it fails with that message.
- A resume command that named only the gateway would resolve the groups, prefix and access again. The prefix
  and access have no home on the gateway before the deployer writes them, and `entitlement-groups` is written
  after the switch, so a resume could pick other groups or create a second set of resources under another
  prefix. The apply now prints the resolved values.
- `az apim show` gives the region as a display name (`East US 2`). The Retail Prices API and the usage reads
  take the ARM name (`eastus2`); the facts convert it as `Install-ClaudeGateway.ps1:580` does.

### Architecture

No component, data flow, identity, schedule or network path changes: the update runs the installer's
existing deployment and switch (`scripts/ClaudeInstallProjection.ps1`), which the diagrams already show.
`entitlement-groups` is one more non-secret named value on the gateway, read by scripts and not by the
policy.
