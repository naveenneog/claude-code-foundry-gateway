# P121 Staged test environment and smoke test, 2026-10-21

### Why

The gateway, the projection and the scheduled sync job were checked live
piece by piece. A disposable environment that deploys resources, then
configuration, and runs one smoke test shows that a person moved between
groups gets their new access and chargeback unit from the scheduled job
alone.

### Acceptance criteria

1. `infra/test-environment/resources.bicep` and `configuration.bicep` build
   with the repository's Bicep version and compose the existing modules.
2. `main.bicep` writes the client-credentials secret named value only when
   `foundryClientSecret` is set; otherwise its output is unchanged.
3. `scripts/Deploy-ClaudeTestEnvironment.ps1` runs each stage alone or all in
   order, refuses a resource group it did not create (tag
   `claude-test-environment`), refuses a `-SyncMinutes` outside 5 to 30, and
   never prints the Foundry secret.
4. Live: a standard-model request returns 200 and a premium-only model 403;
   after the user moves to the premium group and another unit, the next
   scheduled run makes the premium request return 200 and puts the user in
   the new unit in the membership lines, with no operator step.
5. Teardown deletes only the resource group and Entra objects the run
   created.

### Contract

[ADR-0067](../adr/0067-staged-test-environment.md). U202 (open) records the
Graph grant right; U203 (assumed) the FDPO credential.

### RED and GREEN

- `tests/Test-TestEnvironment.ps1` (18 assertions, count guarded) failed
  before the Bicep files and the script existed; it builds both Bicep files
  with Bicep 0.46.1 and checks the script's guards without Azure.
- Live finding, fixed test-first: `@azure/cosmos` 4.10.1 `Item.read()`
  returns a 404 response instead of throwing, so on a projection without an
  access catalog every scheduled run failed at the catalog stage. Both Cosmos
  fakes now return the 404 the same way, which failed 4 sync tests and the
  renewal simulation before `readAccessCatalog` was fixed (`227a3e8e`).
- Live finding: a subscription policy turned off public access on the
  resolver storage, and the code upload failed with 403; the configuration
  now gives that storage private endpoints.
