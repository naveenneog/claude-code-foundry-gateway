### Contract

P86 replaces P84's unconditional projection-switch refusal with destination-bound renewal evidence, not ARM metadata. ADR-0040 states that the deployer, installer and guided Entitlement path currently refuse projection switching (`docs/adr/0040-projection-preflight-and-switch.md:24-25`), that Graph failures are failures while a successful empty collection is the only empty-group proof (`docs/adr/0040-projection-preflight-and-switch.md:43`), and that P86 admission requires two reconciliation-generation advances inside two hours (`docs/adr/0040-projection-preflight-and-switch.md:72`). ADR-0017 keeps the absolute lease at 7,200 seconds from scan start and requires alerting on remaining lease, not process exit alone (`docs/adr/0017-projection-freshness-and-admission.md:10-31`). The current guides warn that a clean comparison without renewal leads to developer-wide 503 after expiry (`docs/SECURE-PROJECTION.md:491-501`, `docs/SCALE.md:746-764`).

The scheduled reconciler will be an Azure Container Apps Job in the projection VNet. `infra/projection-network.bicep` will add an internal workload-profiles Container Apps environment on its own at-least-/27 subnet delegated to `Microsoft.App/environments`, separate from the resolver subnet in the default `10.10.0.0/16` plan (`infra/projection-network.bicep:43`). The job runs every 30 minutes by default, configurable by parameter, because records expire 7,200 seconds after scan start: a 30-minute cadence tolerates three consecutive missed runs before expiry, while hourly tolerates no missed run plus a late start. The job uses a user-assigned managed identity, pulls a tested digest-pinned image built from `sync/`, and executes the existing Node graph path in `sync/src/apply-projection.mjs` (`sync/src/apply-projection.mjs:18-27`). The registry SKU is a parameter: Basic is the default for standing cost and uses the public ACR endpoint with Entra authentication; Premium is required for a private endpoint. Any cited ACR/Cosmos prices come from the Azure Retail Prices API via `scripts/AzureRetailPrice.ps1`, dated in the docs. The job identity receives Microsoft Graph application permission `GroupMember.Read.All` only through a tenant-admin pack, and receives Cosmos SQL data-plane rights scoped to `/dbs/claude/colls/entitlement`. Forced-tunnel/firewall docs will name required outbound destinations: `graph.microsoft.com`, `login.microsoftonline.com`, the ACR login server and data endpoint, and the Cosmos private endpoint through private DNS.

Each successful run writes entitlement records and destination-bound status records into the same `entitlement` container because the job is allowed to write only that container. Status records are precisely shaped: `id = projection-status::<tenantId>::<reconciliationGeneration>`, partition key `/oid = projection-status::<tenantId>` so it can never be a GUID, `type = projection-reconciliation-status`, and `ttl = 21600` to keep at least six hours of history. They include tenant, Cosmos account/database/container identity, run id, image digest, entrypoint, normalized command, dry-run/override detector results, reconciliation generation, started/finished times, tier and business-unit member counts, write counts and the oldest entitlement expiry. Tests will prove resolver point reads by oid cannot return status records, query paths filter them out, and the job never deletes or overwrites a status record from another generation. A Graph-denied or partially unreadable run writes no entitlement records and no success status; it fails visibly and logs the denied read to Log Analytics. Empty groups are represented only after a successful Graph collection, following the existing Graph membership contract (`scripts/ClaudeGraphMembership.ps1:45-69`, `scripts/ClaudeGraphMembership.ps1:141-169`).

Admission for `-FlipAfterCleanCompare`, `-FlipProjectionAfterCleanCompare` and the guided Entitlement switch will run fixed repository code through the existing in-VNet runner (`scripts/ClaudeRunner.ps1`), not the job definition's command. That code reads Cosmos status history and oldest entitlement expiry and returns JSON to the caller. Admission also reads ARM for the Container Apps job definition and requires the pinned image digest plus no command or args override. Both Cosmos evidence and ARM definition pass, or the switch refuses. The evidence must be bound to the exact destination account/database/container and tenant, the oldest expiry must have at least 60 minutes of margin, the generation must have advanced at least twice in the previous two hours, and the newest successful renewal must be within 45 minutes. Dry-run, `--whatif`, shell command overrides, alternate entrypoints, missing action group and wrong-destination evidence are refusal reasons with plain-language remedies and the expected wait when there is too little history. Rollback to `named-value` remains available and documented after refreshing and comparing the named-value lists.

Azure Monitor scheduled-query alerts will be deployed for no successful run in 45 minutes, oldest expiry margin below 60 minutes and Graph read denied or failed. An action group with email receivers is a required deployment input; without it, deployment warns that alerts notify no one and admission refuses the switch by naming the missing action group. Log Analytics receives structured run events from the job. The Bicep and scripts will not create or grant the Graph app role directly except in the tenant-admin pack that a Privileged Role Administrator or Global Administrator runs once. The ADR/docs will record the deployment order: deploy projection and job; tenant admin grants `GroupMember.Read.All`; runs succeed; evidence accumulates for about 60-90 minutes on the 30-minute schedule; switch; rollback. The ADR/docs will also state Cosmos write cost for 500, 5,000 and 500,000 members on 30-minute and hourly schedules, using README.md's 365 million writes/month and about USD 538/month hourly 500,000-member basis (`README.md:27-31`).

### Acceptance criteria

1. Given a projection VNet deployment, Bicep defines an internal workload-profiles Container Apps environment on its own delegated subnet, a configurable scheduled job defaulting to 30 minutes, a user-assigned managed identity, scoped Cosmos SQL data-plane access to the `entitlement` container, Log Analytics integration, an email-backed action group input and scheduled-query alerts.
2. Given the tenant-admin pack, a privileged administrator can run either the script or the documented `az rest` commands to grant Microsoft Graph `GroupMember.Read.All` to the job identity; the accelerator itself does not silently grant it.
3. Given Graph denies any required group read, the job exits nonzero, logs the failure, writes no entitlement records and writes no success status that admission can consume.
4. Given a successful graph reconciliation, unchanged members are renewed, status evidence is written to Cosmos, and the oldest expiry/generation history can be read from the destination container.
5. Given good Cosmos evidence and a good ARM job definition, the deployer, installer and guided flow admit the projection switch; given missing action group, stale, missing, wrong-destination, dry-run override, command/args override, wrong-image/entrypoint, single-generation evidence or too little history, each refuses with the reason, remedy and expected wait where applicable.
6. Given rollback to `named-value`, the existing path remains available and warns that lists must be refreshed and compared before rollback.
7. Documentation records the renewal job, tenant-admin step, alerting, admission, rollback, offline proof and live-tenant limits without real tenant or subscription ids.
