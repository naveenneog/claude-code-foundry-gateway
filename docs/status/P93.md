### Milestone 2 documentation, architecture and mutation proof

The UI guide is `docs/INSTALLER-UI.md`. It covers the workstation and Cloud Shell start command, the
static fallback, the security model, the form sections and the stub screenshots
`docs/guide/installer-ui-overview.png`, `docs/guide/installer-ui-preflight.png` and
`docs/guide/installer-ui-run.png`. `guide/capture-installer-ui.mjs` captures them against the stub.

Architecture source `docs/architecture/18-installer-ui.json` renders

completed:

```powershell

```

Mutation proof is in `docs/measurements/p93-mutations.json`. Fifteen targeted mutants were caught by
`tests/Test-InstallerUi.ps1` with the 17-check baseline: token, Host allowlist, OPTIONS, CSP, body
limit, 409, step-id validation, streamed-line redaction, temporary directory removal, unset-state
collection, empty-selection refusal, full-run confirmation, file structural check, schema drift and
business-unit id rules.

The static fallback test opens `tools/installer-ui/index.html` with Playwright. It uses the installed
Edge channel when present and falls back to the Playwright Chromium bundled for local development. On
this workstation, `msedge` is available and `chrome` is not installed at Playwright's standard channel
path.

Lead check after `3eb7893` found two business-unit editor defects: the first Add team click used a
stale parent selector after a unit id edit, and the JSON view threw uncaught parse errors while text
was partial. The browser test now drives the exact first-click flow and an invalid-then-valid JSON
round trip. Both regressions have mutants in `docs/measurements/p93-mutations.json`.

Lead mutation check after `0b0940d` found that the page and tests used different model copies. The UI
model is now one classic file, `tools/installer-ui/ui-model.js`, loaded by both `file://` and server
mode as `globalThis.ClaudeInstallerUiModel`; tests execute the same file with `node:vm`, and a
structural assertion rejects model function definitions inside `installer-ui.js`. The dead
`/ui-model.mjs` route is removed. The previous unset-state and business-unit mutation evidence against
`ui-model.mjs` is marked superseded in `docs/measurements/p93-mutations.json`.

The same lead check found missing coverage for prefill redaction and identity tenant display. Prefill
now parses raw PowerShell stdout and redacts `parsed.error` in the route under test. The test stub
returns an error containing every redaction sentinel shape and asserts none survive. The identity test
asserts the route and browser banner show user, tenant id, subscription name and subscription id.

Council round 1 security work started with the highest-priority items. The UI now uses a one-use URL
token only for the first top-level GET, then cookie plus same-origin CSRF header for POST APIs;
`POST /api/commands?token=...` and a second bootstrap are refused. POST routes require
`Content-Type: application/json`; child-spawning routes check Origin/Sec-Fetch-Site. Prefill changed
to POST and validates SubscriptionId, FoundryAccount and FoundryResourceGroup before any `az` call.
The Windows marker test proves invalid prefill input does not reach the `az.cmd` stub.

S4 is implemented in the same security area: non-loopback `--host` now requires
`--allow-host <host[:port]>`; the allowed host is used for the allowlist and printed URL; refused Host
requests log Host and `X-Forwarded-*` diagnostics to the terminal only. The test verifies the browser
receives only the generic 403 body while the terminal log contains the proxy shape.

Lifecycle round 1 started with L1 and L2. Run admission now claims an owner token synchronously before
awaiting request body reads, and release only clears the lock for the owner. The stream route validates
empty and unknown steps before `writeHead`; those failures return JSON 400 responses rather than empty
200 streams. The concurrent stream test starts two overlapping requests and observes one child
invocation, one 200 and one 409.
