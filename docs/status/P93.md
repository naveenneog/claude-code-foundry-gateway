### Council round 7 fix R7-2, 2026-10-06

The Azure lease takes an optional callback that it calls with the operation name when a read waits
behind the current holder, and the server passes it from its options
(`tools/installer-ui/azure-lease.mjs:1-2`; `tools/installer-ui/azure-lease.mjs:77`;
`tools/installer-ui/server.mjs:145`). `R3-4 shutdown closes the Azure lease before queued reads can

`tests/installer-ui-g8.test.mjs:429-471`). RED: before the callback existed, the test failed with
`The preflight did not wait for the Azure lease within 30000 ms`.

Lead finding: with the barrier in place, the test failed with `expected: 'fulfilled'` and
`actual: 'rejected'`. Shutdown closed every connection before the refusal of the queued preflight
was written, so the browser received a closed connection instead of `installer-ui-stopping`. The
50 ms version passed because the preflight usually reached the lease only after shutdown had closed
it, which tested a later read, not a queued one. Cleanup now yields once after it closes the lease
and stops the child processes, so the refusals of queued reads are written, then waits at most 1 s
for responses that have ended but not yet finished before it closes connections; open streams are
not waited for (`tools/installer-ui/server.mjs:155`; `tools/installer-ui/server.mjs:171-189`;
`tools/installer-ui/server.mjs:311-312`). The guide and ADR-0048 record the rule
(`docs/INSTALLER-UI.md:146-147`; `docs/adr/0048-installer-ui-local-server.md:123-124`).

and 300 ms between the barrier and shutdown, the test passed twice, `r3-4-2` (shutdown does not
close the lease) failed it with `expected: 503`, `actual: 500`, and `r7-2-1` (no write before the
